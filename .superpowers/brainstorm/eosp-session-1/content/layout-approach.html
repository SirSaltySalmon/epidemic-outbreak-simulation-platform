Dashboard Structure: How should the two user modes work?

You described two audiences: a visitor who sees cached results without triggering compute, and a researcher who can run live forecasts and observe the model as it executes. How should the UI separate these?

A

Mode Toggle at the top

One URL, two faces. A prominent switch in the header — "Situation Report" vs "Researcher Console" — instantly swaps the entire interface. Visitor mode is the default and shows only pre-cached data. Researcher mode reveals the live run panel, inference console, and parameter controls. No routing, no login wall.

Strengths

  • Single shareable URL
  • Smooth progressive disclosure
  • Researcher mode feels "unlocked" not separate

Tradeoffs

  • Researchers always start in visitor view
  • Mode state lost on refresh
B

Tabbed Application with Role-gated Tabs

Four persistent tabs across the top: Situation · Scenarios · Model Intelligence · Researcher Console. The first three are always visible. The fourth tab is either locked (shows a lock icon) or auto-unlocked. Each tab is its own focused view with its own visualisations.

Strengths

  • Matches the PRD's 4-tab spec exactly
  • Clear navigation mental model
  • Each view can be deep-linked

Tradeoffs

  • Researcher Console tab could feel tacked-on
  • Users may miss what's on other tabs
C

Landing Dashboard + Side Drawer for Researchers

The main page is a rich, always-visible outbreak intelligence dashboard — world map, forecast chart, scenario cards — all fully rendered from cache. A persistent "Run Analysis →" button/panel on the right edge slides out a researcher drawer overlay with the inference console, live simulation progress, and parameter controls.

Strengths

  • Visitor experience is premium and uncluttered
  • Researcher tools don't pollute the main view
  • Drawer can show live progress without navigating away

Tradeoffs

  • Drawer UX can feel cramped on smaller screens
  • Researcher workflow split across two surfaces
