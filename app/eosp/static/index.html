How this simulation works

This page shows recorded outbreak lines alongside a computer simulation of how infection could spread among a small, carefully defined group of people tied to major airports—not the whole global population, and not everyone still in the original travel context.

The colored bands on the chart are uncertainty: the model is run many times with slightly different random outcomes so you can see a plausible range, not a single guess.

  • The map shows where risk is elevated in the simulation on each day, using the same airport “patches” people move through—not a census of everyone who lives there.
  • Scenarios (sidebar) change assumptions—such as cutting some contacts—so you can compare “what if” without pretending any option is certain.
  • Limitations: schedules come from public flight-route data (connections, not your personal ticket); counts near hubs are placeholders until official numbers are plugged in; the model cannot predict real-world policy or behavior changes it does not know about.

Technical details

Cohort. The default world tracks eighty agents: twenty placed at each of four hub IATA codes (JNB, DOH, ZRH, AMS), sized from the static baseline JSON. They represent a contact / onward-travel ring around known case locations, not the full ship population or general public.

Movement. After day zero, each agent’s airport follows a Markov step on directed edge weights from OpenFlights routes.dat (weekly row counts). Country labels from airports.dat support a configurable domestic continuation bias; if domestic onward edges are missing, the agent stays. Optional environment overrides: EOSP_OPENFLIGHTS_ROUTES, EOSP_OPENFLIGHTS_AIRPORTS.

Dynamics. Transmission uses itinerary patch co-location and same-flight mass action (Track B). Agents follow a compartment SEIPHR+D style update with stochastic daily progression. Edge layers are empty in the default build so contacts are driven by patch mixing, not a static ship graph.

Inference vs. initial conditions. Bayesian posteriors supply transmission and disease parameters (e.g. transmissibility, contact intensity, incubation, severity). Initial exposed / infectious / recovered / deceased counts are allocated from aggregated case records onto the cohort. When raw totals exceed the cohort size, counts are scaled proportionally with largest-remainder integer rounding; metadata may include seed_scaling. This is not an independent draw of “sick or well” for every agent from the posterior.

Scenarios. Scenario specs adjust parameters and network modifiers before ensembles are run; comparison responses are derived from cached forecasts per scenario.

Provenance. Flight baseline snapshots hash canonical JSON and may incorporate a SHA-256 of the routes file. OpenFlights derivatives are ODbL—see project README for attribution when publishing graphs or downstream datasets.
